# D1.7 serialized dataset session checkpoint

DatasetSession now owns the open backend file, captured factory, optional save-notice sink, serialization queue, busy/closed state, refresh/open replacement and close/drain. DuckDBDocument retains URI, VS Code trust/configuration/notifications, live scheduling, query/catalog/selection state and filesystem-lock ownership. Its compatibility methods delegate to the host-free session.

The queue retains the existing eight-live-job and hard 64-job depth limits, unique guard identities, execution-time authorization, stale-read supersession and failure-settled chaining. Saves supply no supersession guard. Busy live ticks still yield. Reopen runs inside the same serialized host calls, uses the read-only in-place shortcut before reading settings, invalidates after installing the new file and before disposing the old file, preserves exact open errors and disposes a late handle after close. No mutation retry was added.

Closing marks the session closed synchronously before immediate host selection/live cleanup and read interruption. Queued jobs refuse at execution; active trusted saves drain before backup comparison, disposal and filesystem-lock release. Idle cleanup retains its synchronous path. Save-notice sinks remain available after editor closure. Reentrant close calls share the same completion promise.

Intentional failure-path hardening accompanies the ownership boundary: throwing immediate-close or interruption callbacks cannot prevent draining; a throwing summary cannot prevent disposal; final host lock-release cleanup runs even if file disposal throws; final host callback failures are contained. A throwing invalidation callback also releases the replaced old handle. File-disposal errors remain rejected with their original identity. This differs from legacy exceptional cleanup paths that could skip later cleanup; ordinary behavior and errors are preserved.
